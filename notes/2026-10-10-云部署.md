# 2026-10-10 ｜ Day 15 ｜ 上公网：从「我电脑上能跑」到「谁都能打开」

## 今天要回答的问题

**公网地址第一次打开时，你第一个想确认的是哪一件事？**

答：**这个地址背后跑的，到底是不是我刚才写的那份代码。**

这个问题看着简单，其实问的是「本地」和「公网」之间那道鸿沟。从"我电脑上能跑"到"一个陌生人在手机上打开"，
中间隔着好几道关卡，每一道都可能悄悄出问题：

| 关卡 | 可能出的问题 |
|---|---|
| 代码上传 | 传的是旧版本 / 部分文件没传上去 / 依赖没装 |
| 云端运行 | 跑的是哪个运行时、哪个版本的代码 |
| 地址映射 | `/api/health` 这个路径，是不是真的指到了我写的那个函数 |
| 环境 | 有没有打到错误的环境（比如测试环境当成了正式环境） |

**所以 health 接口返回的那几个字段，一个都不是凑数的**：

| 字段 | 回答的问题 |
|---|---|
| `service` | 这是不是我的服务（不是别人的、不是某个默认示例） |
| `version` | 是哪一版代码 |
| `env` | 打到了哪个环境 |
| `time` | **这个响应是不是"现在"生成的** |

`time` 是最关键的一个——它是实时的。如果返回的时间一直不变，就说明你看到的不是代码在跑，
而是某个缓存，或者一个静态文件在冒充接口。**光看"返回了 JSON"是不够的，得看返回的东西能不能证明它活着。**

**第二个想确认的**：这个公网地址，是不是谁都能打开？
公网意味着任何人都能访问，所以**不能把整个项目目录一股脑传上去**——
课程文档、自测脚本、截图，这些都是开发过程的产物，不该出现在公网站点上。
所以写了 `deploy-frontend.cjs`，用**白名单**（而不是"排除掉那些不该传的"）来挑文件。

> 为什么是白名单：排除法一旦漏写一项，那个文件就被悄悄传上去了，事后很难发现；
> 白名单漏写了会立刻因为"文件不存在"报错，当场就能发现。

## 今天最大的认知：云函数默认是"关着门"的

我原以为"部署个函数就能用网址访问"。不是。

**云函数生来是给云开发内部调用的**（小程序、App SDK 里 `callFunction` 那种）。
要让它能被浏览器用网址访问，得额外做一件事：**HTTP 访问服务**——把某个公网路径映射到某个函数上。

部署命令里的 `--path /api/health` 就是干这个的：

```
https://<服务ID>.service.tcloudbase.com/api/health
                                          └────────┬────────┘
                                          这段是「HTTP 访问服务」加的
```

这也解释了为什么"函数部署成功了"和"网址能打开了"是两件事——它们是两个独立环节，
任何一个出问题，表现都是"打不开"，但原因完全不同。这也是我第一个接口选 health 的原因：
先把整条链路走通，出问题时能一眼看出是**链路问题**还是**业务问题**。

## 接口契约：为什么值得专门写一份文档

今天的产出之一是 `api-contract.md`。它的价值在于——**它是前端和后端之间唯一的那份"合同"**。

不写契约会怎样：前端按自己的想象写请求，后端按自己的习惯返回数据，
两边各自都"对"，一对接就错。然后开始互相甩锅："我这边测试是通的啊。"

今天定下的两条核心约定：

### 1. 判断成败看 `code`，不看 HTTP 状态码

```json
成功：{ "code": 0, "message": "ok", "data": { } }
失败：{ "code": 40500, "message": "只支持 GET 请求", "data": null }
```

为什么不能只靠 HTTP 状态码：**状态码有可能被中间的网关、CDN 改写**，
而 `code` 是我们自己的代码决定的，靠得住。

### 2. 但两者语义必须一致

`code` 和 HTTP 状态码不能各说各话（比如 HTTP 说 200、code 说失败），否则人会看糊涂。
让它们语义一致：人看状态码快速判断，程序看 `code` 精确定位，监控和日志两边都能用。

错误码规则定为 `HTTP状态码 × 100 + 两位细分`（400 → `40000`）。
好处：不查表也能从 `code` 反推出 HTTP 状态码。

## 技术要点（今天弄明白的几件事）

### 集成响应的 `body` 必须是字符串

云函数有两条返回路线：

- **直接返回对象** → 平台自动转 JSON，但状态码固定 200、响应头也改不了
- **返回「集成响应」** `{ statusCode, headers, body }` → 状态码和响应头都能自定义

我选了后者（因为契约要求状态码和 `code` 一致、还要禁掉缓存）。
**坑在这里**：集成响应里的 `body` 必须是 `JSON.stringify()` 之后的**字符串**。
直接把对象塞进 `body`，平台会当成别的东西处理，返回的内容就不是你想要的 JSON 了。

### 一个命名要避开的雷

云函数返回的对象里如果**恰好有 `statusCode` 字段**，可能被平台误判成"这是一个集成响应"，
而你本意只是返回一段普通数据。所以业务字段名要避开平台保留字——
我们的响应里用 `code` 而不是 `statusCode`，正好绕开了。

### 静态托管必须先在控制台手动开通

CLI 只负责上传，**不会帮你开通静态网站托管**。没开通就直接部署，会报 `Hosting not enabled`。
另外开通静态托管还有个前提：环境必须是**按量计费**的。
