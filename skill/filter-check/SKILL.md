# filter-check — 标签筛选交互检查

> 本 Skill 只服务于本项目（学习笔记站 `my-website`）。它检查的是**筛选交互**，不碰别的功能。
> 归属：Day 12 任务产出。为什么建它：筛选交互有三种情况，其中「无结果」在页面上不一定点得到，
> 人眼测试容易漏掉，所以把检查步骤固化下来，避免每次改完 `app.js` 都要重新想一遍该测什么。

## 用一句话说它检查什么

**筛选交互的三种情况是否都正确：有结果时只剩该标签的笔记、无结果时显示空状态而不是白屏、清空筛选后完整列表恢复——以及键盘能不能操作、读屏能不能听到结果。**

## 什么时候用

- 用户要求检查/验证筛选功能
- 改动了以下任一文件后做回归：`app.js`（筛选逻辑、tag-bar、空状态）、`components.js`（卡片、状态盒）、`mock-data.js`（标签数据）
- 提交前想确认 AC-4、AC-7 仍然成立

## 前置条件

1. 浏览器验证需要本机 Edge + 已安装的 puppeteer-core：
   `NODE_PATH="C:/Users/胡政/.workbuddy/binaries/node/workspace/node_modules"`
2. 本地服务器：`--browser` 模式会**自己检查 8080 端口**，没有服务就自动起一个静态服务、跑完自动关。

   手动开服务仅供自己在浏览器里点着看：`python -m http.server 8080`
   （**不能双击 index.html**，`file://` 协议下 fetch 会被拦）

## 检查步骤

### 第 1 步：静态检查——三种情况在代码里是否都有分支

不要只跑浏览器，先读代码确认逻辑分支存在。看 `app.js` 的 `renderNotes()`：

| 要确认的点 | 怎么看 | 不通过的样子 |
|---|---|---|
| 有结果分支 | `visible.length > 0` 时渲染列表且清掉状态区 | 列表渲染了但状态区没清，两个同时显示 |
| 无结果分支 | `visible.length === 0` 时 `showState("empty", ...)` | 直接白屏，或只有空白列表 |
| 清空恢复分支 | 再点同一标签时 `activeTag` 回到 `"全部"` | 点了没反应，或筛选卡住无法解除 |

**重点**：还要确认「无结果」**在页面上点得到**。标签栏只列出数据里存在的标签，所以点任意标签都至少筛出 1 篇——「无结果」这一路靠点击走不到。Day 12 加了一个演示入口解决它：

```
http://localhost:8080/?tag=不存在的标签
```

用这个网址可以直接以"筛不到结果"的状态打开页面，验证 AC-7 的空状态。检查时不要因为"点不出来"就跳过这一路。

### 第 2 步：跑自动化检查

```bash
cd my-website
node skill/filter-check/check-filter.cjs            # 只做静态检查
node skill/filter-check/check-filter.cjs --browser  # 加本机 Edge 实测（8080 没服务会自动起一个）
```

浏览器模式需要 puppeteer-core，用这个环境变量指向已装好的位置：

```bash
NODE_PATH="C:/Users/胡政/.workbuddy/binaries/node/workspace/node_modules" \
  node skill/filter-check/check-filter.cjs --browser
```

脚本会逐项打印「通过 / 失败」，并在最后给出总表和结论块。任何一项失败都不要继续往下走，先修。

### 第 3 步：浏览器实测三种情况

脚本的 `--browser` 模式已经覆盖，也可以手动点一遍：

1. **有结果**：点一个有多篇笔记的标签 → 卡片数应减少，且每张卡片都含该标签
2. **无结果**：打开 `?tag=不存在的标签` → 必须出现空状态文案，**不能是白屏**，且该标签在标签栏里是选中态
3. **清空恢复**：点「全部」→ 卡片数回到总数；再点一次当前标签也能解除筛选

### 第 4 步：可访问性检查（余力加练）

| 检查项 | 通过标准 |
|---|---|
| 标签按钮可键盘操作 | 按钮是原生 `<button>`，Tab 能聚焦，Enter 能触发 |
| 选中状态可被读出 | 选中标签有 `aria-pressed="true"`，未被选中的是 `"false"` |
| 筛选结果有播报 | 筛选后 live region 里有文案（如「已筛选标签「Git」，共 3 篇」） |
| 焦点可见 | 聚焦的标签按钮有可见描边（`:focus-visible` 生效） |
| 空状态对读屏可见 | 空状态是文本而非纯图标，且出现在 DOM 中（不是 CSS 伪元素画的） |

### 第 5 步：输出结论

按下面格式给结论，一项一行，不给"差不多"：

```
筛选三态检查 — <日期>
[通过] 有结果：点「Git」剩 3 篇，全部含该标签
[通过] 无结果：显示空状态「标签「XX」下还没有笔记」
[通过] 清空恢复：点「全部」回到 8 篇
[通过] 可访问性：aria-pressed / 播报 / 焦点描边 均正常
```

若有失败项，必须写清**哪个文件的哪一段**导致问题，以及修法。

## 常见坑（踩过才写下来）

1. **空状态点不到**：mock 数据里每个标签都至少有一篇笔记时，「无结果」路径永远走不到。Day 12 已加 `?tag=不存在标签` 入口解决；如果你看到这个参数被删了，要提醒用户 AC-7 的验证路径会断。
2. **两种空状态文案混用**：全站没笔记（首次使用）和"筛选没结果"（AC-7）是两回事，文案不同。`renderNotes()` 里靠 `activeTag !== "全部"` 区分，改动时别把两者合并成一句。
3. **`aria-pressed` 没跟着更新**：`buildTagBar()` 是重建整个标签栏，容易忘记在新按钮上重设 `aria-pressed`。
4. **筛选后没播报**：`announceFilterResult()` 要在 `renderNotes()` **之后**调用，否则读到的是旧状态。
5. **状态区和列表同时显示**：`renderNotes()` 里必须"要么清状态、要么显示状态"，不能两个都留。
6. **异步检查没 await**：`check-filter.cjs` 里浏览器检查是 async，必须 `await` 后才打印总结，否则结论会在检查跑完前就输出（Day 12 亲手踩过，表现为"浏览器实测"标题下方空无一物）。
7. **该筛选的标签不在栏里**：从 `?tag=` 进页面时，若这个标签在数据里不存在，`buildTagBar()` 要把它补进栏里并高亮，否则用户看不到自己在筛什么。
8. **忘了先开 8080，误判成页面坏了**：`--browser` 早期版本不自带服务，重跑时若 8080 没人监听，puppeteer 会卡 8 秒然后抛 `Waiting for selector ".note-card" failed`。这个报错**指向选择器，实际是端口问题**，很容易让人去改 `components.js`。现在脚本会自己起服务并在输出里写「8080 无服务，已自动启动本地静态服务」；看到这行说明是它自己起的，属正常。

## 不做什么

- 不检查筛选以外的功能（展开收起、四种页面状态另有 Day 11 的脚本）
- 不修改 `PRD.md` 的验收标准（要改先问用户）
- 不新增依赖：浏览器验证复用已有的 puppeteer-core，不下载新东西
