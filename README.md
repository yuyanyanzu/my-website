# 胡政的学习笔记

一个公开的学习笔记站：每天学什么，按时间线看全。纯 HTML/CSS/原生 JS，笔记用 Markdown 写、Git 提交即发布。

> 需求依据见 `PRD.md`，技术路线见 `TECH_DESIGN.md`。

## 本地运行（Day 7 版）

**重要：不能直接双击 `index.html` 打开**——页面用 JS 拉取 `notes/` 目录下的 Markdown 文件，双击打开（`file://` 协议）会被浏览器安全策略拦住，页面会一直显示"笔记加载中"。必须先起一个本地服务器。

方式一（推荐，电脑装过 Python 即可用）：

```bash
# 1. 进入项目目录（my-website 文件夹）
# 2. 启动本地服务器
python -m http.server 8000
# 3. 浏览器打开
#    http://localhost:8000
# 4. 停止服务器：在终端按 Ctrl + C
```

方式二（装过 Node.js 的话）：

```bash
npx serve .
# 按提示打开它给出的 http://localhost:xxxx 地址
```

## Day 8：数据源开关与四种页面状态

主视图现在默认用**本地假数据（mock）**渲染，不依赖真实数据源，方便先调界面。

- **切换数据源**：打开 `app.js`，顶部 `USE_MOCK = true` 用假数据（`mock-data.js`），改成 `false` 则回到读取 `notes/` 真实 Markdown 文件（Day 7 的实现，保留备用）。
- **预览四种页面状态**（浏览器地址栏直接加参数）：

  | 网址 | 看到的状态 |
  |---|---|
  | `http://localhost:8080/` | 先「加载中」→ 再「有数据」 |
  | `http://localhost:8080/?delay=3000` | 加载状态停留 3 秒，方便观察 |
  | `http://localhost:8080/?state=empty` | 空状态（模拟还没有笔记） |
  | `http://localhost:8080/?state=error` | 出错状态（含排查指引） |

- **组件在哪**：卡片、列表、状态提示三个可复用组件都在 `components.js`，业务逻辑在 `app.js`——换数据来源不用改组件。

## Day 11：交互反馈（点击后用户怎么知道"生效了"）

展开/收起不再只是"内容突然变出来"，而是一组同时发出的反馈：

| 通道 | 具体表现 |
|---|---|
| 文字 | 顶部通知条：「已展开《标题》」/「已收起《标题》」 |
| 动效 | 正文从 0 高度滑出（260ms），不是瞬间跳出 |
| 视觉 | 提示语从"▼ 展开全文"变"▲ 收起"，展开的卡片左侧亮起蓝色竖条 |
| 无障碍 | `aria-expanded` 同步更新 + 读屏软件播报同一句话 |

标签筛选也有反馈：会提示「已筛选标签「前端」，共 3 篇」。

**自己验证这三种反馈**：

| 想验证 | 怎么做 |
|---|---|
| 动效有没有生效 | 点一张卡片，看正文是"滑出来"还是"蹦出来" |
| 连续操作会不会乱 | 快速连点同一张卡片 20 次，再点其他卡片，看有没有卡住或错位 |
| 键盘能不能用 | 按 `Tab` 让焦点落到某张卡片（有蓝色描边），按 `Enter` 或空格展开 |
| 通知条会不会堆积 | 连续点不同卡片，通知条应只显示最后一次结果，不排队 |

**实现放在哪**：反馈层单独拆成 `feedback.js`（通知条 + 读屏播报两个函数），卡片交互在 `components.js` 的 `toggleCard()`。这样以后别的地方要提示，直接调 `showToast()` 就行。

**动效可关闭**：系统里开了"减少动效"的用户，动画会自动关掉，但文字提示和箭头变化全部保留——弱化的是"动"，不是"反馈"。

## 如何发布一篇新笔记

1. 在 `notes/` 目录新建一个 `.md` 文件，头部按固定格式写四行字段：

   ```markdown
   ---
   date: 2026-09-28
   title: 笔记标题（≤30字）
   tags: 标签1、标签2
   summary: 一句话摘要（≤50字）
   ---
   正文用 Markdown 写。
   ```

2. 打开 `app.js`，在顶部 `NOTE_FILES` 清单里加一行新文件名。
3. `git add` + `commit` + `push`，GitHub Pages 上线后即自动出现（Day 7 本地版刷新页面即可看到）。

## 自测脚本（开发用，不参与页面运行）

把"改完跑一遍看有没有坏"写成脚本，避免每次都靠肉眼反复点。

| 脚本 | 用途 |
|---|---|
| `day11-interaction-test.cjs` | 交互反馈 + 连续操作压力测试（含连点 100 次），用内置 DOM 桩，不需要浏览器 |
| `day11-browser-check.cjs` | 用本机 Edge 真跑页面，验证展开动画、通知条可见性、键盘操作 |

```bash
node day11-interaction-test.cjs    # 随时可跑，不依赖浏览器
node day11-browser-check.cjs       # 需要本机装了 Edge，且本地服务器已在 8080 运行
```
